## 本轮实现

### 安全诊断与页码门禁

- DOCX 页码开关仍为内部配置 `DOCX_PAGE_LOCATION_ENABLED`，默认关闭；探针显式设置为开启。
- 探针显式将 `OCR_HTTP_RETRY_ATTEMPTS` 设为 `0`，本轮只发起一次甲方文档解析请求。
- 外部页号校验严格要求完整的 `1..total_page_number`；空白物理页可以只有页元数据、没有详情块。
- sidecar 允许无关本地结构、无法唯一定位的重复文本和未独立识别的单元格跳过或继承表格页码；只对正式展示的 `diff_items` 双侧位置和公开风险卡关联的证据位置强制映射。
- 规则/映射诊断和非公开复核项只做 best-effort，不扩大公开页码门禁。
- 错误链保留 `failure_stage`、`failure_code`、页数、外部详情页/结构数、本地结构数、候选映射数和未映射数等安全摘要；不记录正文、完整响应、URL 或鉴权信息。
- 大表映射改为显式依赖栈，超过状态阈值时使用顺序线性匹配，避免递归深度溢出。
- 页码仍只在建议生成后的结果持久化节点写入，不改变事实 ID、逻辑 `location_key`、抽取 payload、checkpoint 命中键或摘要。

### 首次外部探针

- 输入：一份脱敏 DOCX（仅记录文件名，不记录正文）。
- 请求次数：1；无客户端重试。
- 首个明确子错误：`failure_stage=MAPPING`、`failure_code=RecursionError`，发生于表格单元格映射调用的序列对齐器。
- 该异常发生在 sidecar 汇总前，因此本次崩溃响应的页数、外部详情页数、结构数和候选数没有可靠值，未伪造填充；探针现已对未知异常只输出固定安全错误和异常类型。
- 该错误不是外部 `page_id` 缺失的证据。本轮已修复映射器并用本地大表用例验证，但按“失败只处理首个明确子错误、不原样重跑”的门禁，没有再次调用甲方接口。
