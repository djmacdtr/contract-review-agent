1. 正式任务下载成功，在 `PARSING / 35%` 失败，失败发生于首个目标 DOCX 的外部页码解析阶段。
2. 任务输入顺序为目标合同、合同模板、辅助资料；路由代码按顺序串行解析，不存在三份文件并发压垮上游的问题。

## 结论

当前正式验收失败的直接原因是本机 Docker Worker 到甲方 OCR 的网络路径异常，而不是 DOCX 页码映射、文件下载、鉴权配置或甲方 OCR 服务整体不可用。宿主机通过集团零信任网络可以访问 OCR，但 Docker Desktop 的桥接/NAT 流量未获得同等网络通路，或在中间网关处被返回 502。

因此，在本机 Docker 网络问题未处理前继续创建正式任务只会重复失败，不应再消耗业务任务或修改页码算法。

## 建议方向

1. 本地最快验收：停止 Docker Worker，改由宿主机虚拟环境运行 Worker，并让其连接 Docker PostgreSQL；测试文件同时由宿主机受控 HTTP 服务提供。API、数据库和控制台可继续按需要运行。
2. 最终交付验收：在甲方内网服务器部署 Docker 后，先从 Worker 容器执行 OCR 只读探针和单文件解析探针，成功后再跑三文件正式任务。
3. 若必须保持本机全 Docker：由网络/零信任运维配置 Docker Desktop/WSL 到甲方网段的路由与放行。该项属于本机网络环境治理，不应写入业务代码。
