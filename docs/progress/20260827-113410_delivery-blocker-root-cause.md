1. 固化宿主机 Worker 的有效配置为 `json_schema`，启动时只记录响应模式、模型名和开关，不记录密钥。
2. 为映射异常保留安全详情：`failure_stage=FACT_MAPPING`、文件 ID、底层错误类别、请求次数和结构纠错次数；不得记录正文或完整模型响应。
3. 暂停继续改造 checkpoint。下一次仅以最新任务作为来源；它已经拥有当前规划身份下的完整抽取 checkpoint，预期可以直接进入映射。
4. 先执行离线回归，确认跨任务复用后 LLM 抽取调用为 0，并确认映射错误详情可持久化。
5. 只授权一次新的三文件任务。验收目标是直接复用抽取结果，只产生映射和建议所需的少量调用，在数分钟内成功或得到明确映射子码。
6. 如果启用 `json_schema` 后映射仍失败，再针对明确子码做小范围修复。优先将映射改为“程序预筛候选 + 小批量模型映射 + 严格合并”，避免一次向模型发送数百条事实；不再反复运行整条抽取链路。
