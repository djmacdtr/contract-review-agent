# DRAFT_REVIEW 黄金标注格式

> 本文件描述的是回归评测机制，不是生产业务大纲。当前 29 个候选只来自一组脱敏目标合同和模板在当前算法版本下的输出，不代表 29 种模板、资料类型、字段类型或固定检查规则。生产 DRAFT_REVIEW 必须根据每次实际传入的目标合同、模板和 1–N 份辅助资料动态识别文档用途、字段、数值和校验关系。

黄金合同和人工标注均保存在仓库外，不得提交合同正文、合同文件或标注清单。

默认文件位置：

```text
D:\work\contract_review\脱敏真实合同\draft-review-golden-annotations.json
```

使用 `scripts/draft_golden.py export` 从目标合同和模板生成或刷新候选清单。候选只包含文件 SHA-256、位置、规范化内容哈希和差异类型，不包含正文。刷新时会按稳定指纹保留仍然匹配的既有人工分类。

业务人员需要为每个候选填写一种分类：

- `RISK`：确认的固定内容风险；
- `ALLOWED_FILL`：模板允许填写；
- `ALIGNMENT_FALSE_POSITIVE`：对齐误报；
- `MANUAL_REVIEW`：当前规则不能可靠判断。

`scripts/draft_golden.py validate` 会校验文件哈希、候选唯一性、遗漏标注和规则变化造成的陈旧标注，并核对实际规则输出：`RISK` 必须继续产生风险，`MANUAL_REVIEW` 必须保留复核，`ALLOWED_FILL` 和 `ALIGNMENT_FALSE_POSITIVE` 必须已被规则抑制。校验输出只有数量、分类计数和哈希，不输出合同正文。存在未分类、分类不符或漂移时命令返回非零状态。

黄金标注只能回答“这组样本在这个算法版本上的已知输出是否退化”，不能证明系统覆盖所有未来合同。新增文档类型、未知字段和新的数值关系必须继续走开放式文档画像、事实抽取、证据校验、跨文件语义映射和声明式数值规则，禁止转换成文件名、哈希、客户、正文或位置特例。
