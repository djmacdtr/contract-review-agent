# 合同智能比对  项目进度周报

- 报告周期：2026-08-19 至 2026-08-25
- 当前阶段：核心功能开发与真实数据联调
- 总体状态：放款比对主流程已完成真实文件闭环；起草检查已完成核心能力建设，正在进行大合同、多辅助文件场景的真实链路稳定性验证。

## 一、已完成

### 1. 项目基础与部署能力

- 已完成 FastAPI 服务、异步任务队列、独立 Worker、PostgreSQL 持久化和任务异常恢复机制。
- 已提供任务创建、进度查询、结果查询、历史任务查询等接口，文件统一通过 URL 传入。
- 已完成 Dockerfile、Docker Compose、数据库迁移和 Vue 3 测试控制台，可在 Docker 环境中部署运行。
- 已接入结构化日志、统一错误响应、请求标识、健康检查和 OpenAPI 接口文档。

### 2. 放款阶段合同版本比对

- 已完成原合同与盖章扫描件之间的确定性文字及表格差异比对，不依赖大模型判断文字是否发生变化。
- 已支持 DOCX、PDF 和扫描 PDF；扫描件使用甲方 OCR 服务解析。
- 已实现换行符、`<br>`、零宽字符及常见 OCR 排版噪声归一化，减少无业务意义的差异。
- 已支持删除、缺失、新增、变更以及校验通过等结果分类。
- 已实现字符级差异高亮，仅突出实际变化内容。
- 已支持文件名、页码、段落、表格行列等业务位置展示。
- 已支持页面缺失和连续内容块缺失的聚合识别；OCR 自身漏页或解析不完整仍按任务失败处理。
- 46 页脱敏真实 PDF 比对已完成闭环，双方页面覆盖率 100%，差异数量由初始 2,099 项降至 3 项 OCR 字符差异，未检出数值差异。

### 3. 起草阶段多文档检查

- 已完成“目标合同 + 合同模板 + 1–N 份辅助资料”的任务结构，辅助资料不要求预先指定固定类型。
- 已完成目标合同与模板之间的确定性比对，包括固定条款、允许填写区域、未替换占位符、空白项、表格结构和基础必填项检查。
- 已建立动态事实抽取与跨文件映射能力，可根据实际文档内容识别合同编号、金额、日期、期限、期数、利率、比例、数量及其他未知字段。
- 已实现数值单位、百分比、日期和期限的程序化规范化与精确比较；大模型仅提出事实和对应关系，不直接决定精确数值是否一致。
- 已建立事实来源、文件身份和原文位置校验，确保差异项能够回溯至两侧文件证据。
- 已完成动态语义检查规划和受限规则执行框架，不依赖固定合同模板、固定资料类型或固定检查字段清单。
- 已完成大型及扩展表格的兼容处理，表格结构变化可形成正式差异，不再直接阻断整个起草检查任务。

### 4. 检查结果与展示页面

- 已形成起草检查和放款比对两个独立页面，可分别嵌入甲方不同业务节点。
- 已取消风险等级和人工复核展示；所有不合规项统一作为风险项呈现。
- 已按“检出风险、删除/缺失、新增/变更、校验通过”提供分类切换展示。
- 已隐藏任务 ID、模型名称、置信度、内部错误字段等非业务技术信息。
- 每条正式差异支持左右证据对照、字符级高亮和一条简短 AI 分析建议。
- 当前只返回结构化 JSON 供页面渲染，不生成 Word/PDF 报告文件。

### 5. 甲方内部服务联调

- 已完成甲方 OCR 接口文档审阅、宿主机连通性测试、鉴权验证和扫描 PDF 真实解析。
- 已完成甲方 LLM 网关连通性验证、模型列表获取及结构化输出能力评测。
- LLM 客户端已规避本机代理对集团内网请求的影响，并加入超时、结构校验、错误分类和有限纠错机制。
- 已完成紧凑事实抽取验证：脱敏样本能够返回动态事实并通过 Schema、证据和位置校验。

## 二、进行中

### 1. 大合同 LLM 抽取稳定性优化

- 已完成按最终序列化请求大小进行分批，表格按行拆分并保留单元格位置。
- 已实现非法 JSON 批次的局部二分，避免因单个大表格导致整份文档重新抽取。
- 已限制单文档调用预算和递归拆分深度，防止异常情况下调用次数失控。
- 相关定向回归共 160 项通过；当前仍需完成一次真实三文件端到端复验。
- 最近一次真实复验因临时诊断采集器未正常结束而中止，尚未形成可验收的最终差异和 AI 建议；该问题不涉及公开接口和业务结果结构。

### 2. 起草检查真实链路验收

- 正在使用既定脱敏真实合同、合同模板和辅助资料验证完整链路。
- 待验证阶段包括多文件事实映射、动态数值一致性检查、正式差异生成和逐项 AI 建议。
- 当前不会在真实三文件链路未稳定前扩大到全部辅助资料，避免重复消耗模型调用并降低问题定位效率。

### 3. 里程碑级完整验收

- 当前迭代以定向单元和模块测试为主。
- 全仓测试、PostgreSQL 集成、Docker 镜像重建、Compose 冒烟、数据库迁移检查和大文件性能测试将在本轮功能收口后统一执行。

## 三、下一步计划

1. 修复真实诊断采集器的资源释放和指标落盘问题，完成一次受控的三文件真实起草检查。
2. 根据真实结果调整大合同抽取分批参数，确认事实、证据、数值映射和 AI 建议能够完整闭环。
3. 三文件链路稳定后，加入评审意见、法律合规报告等辅助资料，完成真实多文档交叉检查验收。
4. 使用甲方原型和真实结果继续核对两个独立报告页面的分类、业务位置、差异高亮和建议文案。
5. 执行里程碑完整验收，包括全量测试、数据库迁移、Docker 构建、服务健康检查、任务持久化和日志脱敏检查。
6. 在甲方服务器环境完成文件地址、OCR、LLM 网关和业务系统到 Agent 服务的网络连通验证，并整理最终部署说明。

## 四、风险与需协调事项

- 甲方部署服务器需能够访问业务系统提供的文件 URL、OCR 服务和 LLM 网关；
- LLM 对大合同和大型表格的结构化输出仍需通过真实三文件及多辅助文件场景验证。
- 最高约 200 页合同的耗时、内存占用和并发能力尚需在接近甲方生产环境的服务器上测试。

## 五、本周结论

项目已具备可部署的服务框架和两类合同检查入口。放款比对已经完成真实 46 页文件闭环并达到可用精度；起草检查的模板比对、动态事实抽取、跨文档数值校验和结果展示骨架已经完成，当前重点是提升大合同 LLM 抽取稳定性并完成真实多文档端到端验收。
