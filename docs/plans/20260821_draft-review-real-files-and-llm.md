# DRAFT_REVIEW 真实文件基线与 LLM 接入顺序

## 1. 决策

阶段 A 的真实多文档下载和解析切片完成后，下一步不是在“真实文件测试”和“接入 LLM”之间二选一，而是按以下顺序推进：

1. 使用固定脱敏真实文件集完成解析基线；
2. 使用目标合同与模板完成确定性比对；
3. 接入 LLM，逐文件完成自动分类和有证据的事实抽取；
4. 由程序规范化事实并构建跨文档事实矩阵；
5. 最后使用 LLM 生成受证据约束的风险解释和建议。

原因：解析质量和证据定位是确定性比对、LLM 抽取及交叉核验的共同基础。如果直接接入 LLM，出现错误时无法区分是文档解析、分块、Prompt、模型输出还是事实聚合导致。

## 3. 下一验收：真实解析基线

先用 5 份文件创建一个 `DRAFT_REVIEW` 任务，保留任务 ID 和结构化结果，验收以下内容：

- 5 份文件全部下载和解析成功；
- DOCX 的段落、表格、标题层级及位置证据可用；
- PDF 通过甲方外部解析服务处理，页码、表格和位置证据可用；
- 每份文件返回 SHA-256、页数、块数、表格数、解析器和 warning；
- 不出现静默跳页、正文为空、乱码、重复大段或异常碎片化；
- 记录总耗时及 PDF 外部解析耗时；
- 当前结果仍应明确为 `PARSER_ONLY`，不得把解析成功表述为合同检查通过。

如果解析基线失败，先修解析和结构规范化；不要用 LLM 掩盖解析错误。

## 4. 阶段 B：模板确定性比对

只使用 TARGET 与 TEMPLATE：

- 复用 FINAL_COMPARE 的 N:M 对齐和证据定位；
- 区分模板固定文字与允许填写区域；
- 检查固定条款新增、删除、修改；
- 检查未替换占位符、空白线、疑似漏填和空表格单元格；
- 对金额、日期、比例、期限和编号使用程序精确比较；
- 将原始差异、归并结果和过滤原因全部保留为可追溯结构化数据。

本阶段不依赖 LLM。先建立真实文件上的差异数量和类型基线，避免模型接入后无法判断误报来自哪一层。

## 5. 阶段 C：LLM 单文档纵向切片

真实交叉比对需要 LLM，但首轮只做逐文件处理，不把所有文档一次性放入一个 Prompt。

### 5.1 输入范围

- TARGET：抽取合同中已填写的核心事实；
- 3 份 REFERENCE：分别自动识别文档用途并抽取与合同相关的事实；
- TEMPLATE：主要用于确定性结构和必填规则，不作为已确认业务事实来源。

### 5.2 首版输出

- `DocumentProfile`：开放式 `document_kind`、标题、置信度和证据位置；
- `FactCandidate`：字段键、原始值、来源文件、原文证据、位置和置信度；
- 不存在的字段返回缺失，不允许推测补齐；
- 输出必须通过 Pydantic 严格校验，非法 JSON 或缺失证据时有限重试并安全失败；
- 模型调用失败不影响阶段 B 的确定性结果。

### 5.3 接入顺序

1. 实现集团 OpenAI 兼容网关 Client、超时、有限重试和安全错误映射；
2. 探测 `/v1/models` 和结构化输出能力；
3. 默认使用实际可用的 `GLM-5.2`，以网关模型列表为准；
4. 先对一份辅助资料完成分类和事实抽取；
5. 再扩展到 TARGET 和全部 3 份辅助资料；
6. 保留模型名、耗时、重试次数和失败状态，不记录完整合同 Prompt。

## 6. 阶段 D：跨文档事实矩阵

程序按稳定 `field_key` 聚合 TARGET 和辅助资料的事实：

```text
字段
  ├─ 目标合同候选值
  ├─ 评审意见表候选值
  ├─ 法律合规报告候选值
  └─ 项目方案确认函候选值
      → CONSISTENT / CONFLICT / MISSING / UNCERTAIN
```

首批重点事实建议覆盖：合同主体、项目名称、融资金额、租赁期限、利率或租赁利率、付款安排、担保人、合同编号、审批条件和重要风险限制。

LLM 负责从异构文本中找出和映射候选事实；Decimal、日期、比例、期限、主体名称规范化和一致性状态由程序计算。多个来源冲突时不自动选择所谓正确答案，统一进入人工复核。

## 7. 阶段 E：解释和展示

- 合并模板差异、漏填项、事实冲突和不确定项；
- 风险项必须关联文件 ID、页码或 DOCX 位置和证据文本；
- LLM 只能根据已经生成的风险和证据撰写说明，不新增事实；
- 控制台展示文档自动画像、模板差异、事实矩阵、证据和模型限制；
- 同一组真实文件形成可重复运行的结果快照，用于后续模型、Prompt 和规则回归。

## 8. 当前立即执行顺序

1. 先收口并提交当前阶段 A 的未提交代码，确保真实验收可复现；
2. 运行唯一一次 5 文件真实解析任务并审查结构质量；
3. 解析通过后实现阶段 B 模板确定性比对；
4. 同时准备 LLM Schema 和 Client 的 Mock/错误测试；
5. 阶段 B 有真实基线后，启用真实 LLM 单文档纵向切片；
6. 单文档结果可靠后再实现多文档事实矩阵。

本顺序既能尽快看到真实合同效果，也能避免同时引入解析、对齐和模型三个不可控变量。
