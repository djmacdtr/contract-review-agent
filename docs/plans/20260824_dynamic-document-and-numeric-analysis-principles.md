# DRAFT_REVIEW 动态文档、字段与数值交叉检查原则

## 1. 核心澄清

生产需求不是维护一份固定模板类型、固定辅助资料类型、固定字段或固定数值规则清单。

当前脱敏样本导出的 29 个黄金候选，只是“这组目标合同和模板在当前算法版本下产生的 26 个差异与 3 个表格复核点”。它们用于回归测试和人工评估，不是：

- 29 种合同模板；
- 29 种辅助资料；
- 29 个固定字段；
- 29 条生产检查规则；
- 系统能力边界。

真实运行时可能出现没有见过的文档、字段、数值、表格和对应关系，系统必须动态分析。

## 2. 开放式输入模型

一次起草检查输入：

```text
目标合同 1 份
合同模板 1 份
辅助资料 1–N 份
```

辅助资料不要求调用方提供类型。系统逐文件产生开放式画像：

```text
DocumentProfile
- file_id
- document_kind       开放字符串，可为新类型或 UNKNOWN
- title
- purpose_summary
- confidence
- evidence_locations
```

常见的评审意见表、方案确认函、合规报告只能作为种子示例。模型遇到新文档时应根据正文描述其用途，不因为未命中枚举而停止检查。

## 3. 动态字段发现

系统不预设只有融资金额、期限、利率等固定字段。每份文件应基于正文和结构提取事实候选：

```text
FactCandidate
- semantic_key / display_name
- value_type
- raw_value
- normalized_hint
- source_file_id
- evidence_text
- location
- confidence
```

常见字段可以帮助召回，但未知字段仍可产生新的开放式 `semantic_key`。随后由独立评审核验：

- 字段含义是否符合证据；
- 值是否来自指定位置；
- 不同文档字段是否真的属于同一语义；
- 是否存在上下文条件、时间范围、币种、单位或口径差异。

只有证据完整、语义映射可靠且满足双模型共识门的候选，才能影响自动风险或通过；否则进入人工复核。

## 4. 动态数值交叉比对

### 4.1 目标合同数值发现

从目标合同动态提取所有有业务含义且可定位的数值，包括但不限于：

- 金额和币种；
- 比例、利率和基点；
- 期限、期数和频率；
- 数量、单价和合计；
- 日期和时间区间；
- 编号中的业务数字；
- 表格明细、汇总及公式关系。

这些不是封闭清单。新类型数值允许以新的语义键进入候选集。

### 4.2 在全部辅助资料中动态检索

对于目标合同的每个数值事实，在全部辅助资料中寻找“语义相同且口径可比较”的候选，而不是只查固定文件或固定坐标。

结果状态：

```text
CONSISTENT
  至少一个其他来源提到同一事实，规范化值一致

CONFLICT
  至少一个其他来源提到同一事实，规范化值不一致

NOT_MENTIONED / MISSING
  其他资料没有提到该事实；不自动判冲突

UNCERTAIN
  可能存在对应项，但语义、单位、时间或口径无法可靠确认
```

- `CONFLICT` 生成无等级风险，并列展示全部来源和证据；
- `CONSISTENT` 可以形成通过项；
- `NOT_MENTIONED/MISSING` 是否需要人工复核，由动态校验计划判断，不能一律当风险；
- `UNCERTAIN` 只能进入人工复核；
- 不设置固定来源优先级，不由模型擅自选择“正确值”。

### 4.3 规范化与精确执行

模型只负责提出语义对应、单位口径和声明式公式。程序负责：

- 使用 `Decimal` 解析和比较数值；
- 统一币种标记、千分位、百分比、基点、期限和日期表示；
- 保留来源原始精度，按可解释容差比较；
- 使用白名单声明式 AST 执行 add/subtract/multiply/divide/sum 等有限操作；
- 拒绝未知操作、除零、缺失输入和模型生成代码。

## 5. 动态工作流

```text
下载与解析全部文件
→ 目标合同 vs 模板确定性检查
→ 每份文件开放式画像
→ 每份文件动态事实/数值抽取
→ 独立模型证据与语义复核
→ 主模型/评审模型共识门
→ 跨文件语义聚合
→ 程序规范化与精确数值检查
→ 风险 / 人工复核 / 通过
→ 受证据约束的建议
```

不把全部文件一次性发送给模型；逐文件、逐块处理并使用稳定 `file_id` 和位置证据聚合。

## 6. 允许与禁止

允许：

- 常见文档用途和字段作为 Prompt 示例或种子词表；
- 通用金额、比例、日期和表格解析器；
- 证据驱动的开放式字段和公式；
- 黄金样本用于测量规则/模型回归和 Prompt 漂移。

禁止：

- 固定只处理评审意见表、方案函、合规报告；
- 通过 `reference_type` 决定唯一业务逻辑；
- 只检查预先列举的字段或数值；
- 根据文件名、SHA-256、客户名称或固定正文选择规则；
- 根据当前 29 个候选编写段落号或表格坐标特例；
- 把“其他文件未提到”直接判断为数值冲突；
- 让模型直接执行数学计算或决定精确相等；
- 没有来源证据时生成风险或通过。

## 7. 黄金样本的正确定位

黄金集应逐步增加不同格式和不同业务场景，但每个黄金样本只验证：

- 已确认风险是否仍能召回；
- 允许填写和对齐噪声是否仍被抑制；
- 事实和数值证据是否定位正确；
- 新算法是否造成结果漂移；
- 未知文档/字段是否仍能通过通用流程处理。

黄金候选数量不是稳定产品指标。重新解析、改进对齐或更换样本后，29 可以变成其他数量，这是正常现象。

## 8. 验收方向

未来真实验收除了当前五文件样本，还应逐步覆盖：

- 未见过的辅助资料类型；
- 文件顺序和数量变化；
- 新字段在目标合同和部分辅助资料中出现；
- 同一数值使用不同单位、精度或表示方式；
- 其他资料未提到目标字段；
- 同名字段但口径或时间范围不同；
- 多来源一致、多来源冲突和模型语义分歧；
- 模型无法可靠分类或抽取时的人工复核降级。

验收重点不是“覆盖 29 项”，而是系统能否在不新增生产特例的前提下处理新文档、新字段和新数值关系。
